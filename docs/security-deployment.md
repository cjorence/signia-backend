# Security rollout

The browser sends camera frames to `POST /api/recognition/predict` with its existing Laravel login. Training/catalog/download operations use `/api/admin/recognition/...` and require an active administrator. Existing bearer-token clients remain supported. FSL/AI changes have now been restored with colleague permission. Deploy the matching frontend, Laravel and Python revisions together; full staging integration remains to test.

For local development, Laravel defaults to `http://127.0.0.1:5000`. For production, configure `RECOGNITION_SERVICE_URL` and an unpredictable `FSL_SERVICE_TOKEN` of at least 32 characters in Laravel's private environment. Set the same token and `FSL_ENV=production` in Python. Python now validates the Bearer header and refuses production startup without an adequate token. Keep it private and never put service credentials in Nuxt public settings. Laravel forwards its diagnostic request ID so failures can be matched in both services' logs.

Use real Turnstile production credentials and `APP_ENV=production`, `APP_DEBUG=false`, HTTPS app URLs and explicit CORS origins. Account-code/reset-code endpoints fail closed in production with missing/testing Turnstile secrets or debug enabled. Run `php artisan signia:check-production` against the deployment environment; a nonzero exit should stop a release. This command prints check names, never secret values. It is expected to fail with development settings.

The Laravel gateway limits training videos to 20 MiB and approved video types. Configure PHP `upload_max_filesize` to at least 20M, `post_max_size` to at least 22M, and the reverse proxy's request-body limit accordingly. Python now validates containers/category/label, generates private temporary filenames, cleans up and bounds decoded frames/resolution. Laravel bounds the image field to 2,000,000 characters; configure total request-body limits at the host as well. Ensure proxy/request timeouts accommodate short video processing (up to 120 seconds at the gateway).

Recognition rate limits have independent counters so frame traffic does not consume training or checkout quotas. Training start allows two requests per minute per admin; uploads allow ten. Python serializes shared inference, restricts training/upload concurrency and bounds state/history. Training status and recognition sequences remain process-local, and jobs do not survive restarts. Start with one Python worker/replica and bounded threads, and load-test; do not assume multiple workers share state.

After rollout, verify player inference, admin upload/training/model download, unauthenticated denial, non-admin denial, and two simultaneous learners. Exercise email and provider payment sandbox flows, including stale/duplicate webhooks. Test actual ffmpeg conversion on a host where ffmpeg is installed. Run database concurrency tests on the production database engine, not only SQLite.

Browser tokens still use the existing storage mechanism. A session-cookie migration is intentionally deferred until frontend/API deployment domains are decided. History/purchase pagination, backup restoration, monitoring and load capacity remain separate follow-up work; this patch is not a production-readiness certification.

API failure correlation and sanitized production exception reporting are implemented. See [production-diagnostics.md](production-diagnostics.md) for request references, private log access, daily-file versus host-collected logging, staging verification and the remaining alert/browser coverage. Configure retention and alerts on the chosen host before release; they are not activated by source changes alone.
